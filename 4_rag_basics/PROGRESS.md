## RAG Basics: A Telecom Question-Answering Assistant

Notebook: [rag_demo.ipynb](rag_demo.ipynb)

This exercise builds a simple assistant that answers telecom questions using information from a PDF guide.

The technique is called **Retrieval-Augmented Generation (RAG)**. In simple terms, the assistant first finds the most relevant parts of the guide and then asks an AI model to write an answer using only those parts.

## The Main Idea

Imagine asking a librarian a question:

1. The librarian searches the guide for the most useful paragraphs.
2. The librarian gives those paragraphs and your question to an expert.
3. The expert writes a clear answer based on the supplied information.

The RAG application works in the same way. This is more reliable than asking the AI model to answer entirely from memory.

## What Was Built

### 1. Loaded the API key

The notebook reads the Groq API key from the project's `.env` file. The key allows the notebook to securely connect to the online AI model without placing the secret directly in the notebook.

### 2. Read the telecom PDF

The `PyPDFLoader` tool opens `telecom_guide.pdf`, extracts its text, and keeps track of the page from which each piece of text came.

### 3. Split the guide into smaller pieces

The complete guide is too large and unfocused to send for every question, so it is divided into overlapping pieces called **chunks**.

- Each chunk contains up to about 600 characters.
- Neighboring chunks share about 100 characters.
- The overlap helps prevent useful information from being lost when a sentence or topic crosses a chunk boundary.

### 4. Converted text into searchable meaning

The notebook uses the `all-MiniLM-L6-v2` embedding model to convert every chunk into a list of numbers called an **embedding**.

An embedding represents the meaning of text. Texts with similar meanings receive similar numerical representations, even when they do not use exactly the same words.

### 5. Stored the chunks in ChromaDB

ChromaDB stores the embeddings together with their original text and page information. It acts as a meaning-based search system for the telecom guide.

The database is created in memory for this exercise. It must be rebuilt after restarting the notebook because it is not saved permanently to disk.

### 6. Tested the search

The notebook asks a sample question about VoLTE. The retriever searches ChromaDB and returns the three chunks whose meanings are closest to the question.

This test checks that the application can find useful information before involving the AI model.

### 7. Assembled the RAG chain

The notebook connects the following parts into one workflow:

1. Receive a question.
2. Retrieve the three most relevant chunks.
3. Join those chunks into a context section.
4. Send the context and question to the AI model.
5. Return the model's answer as normal text.

The answer is generated by the `openai/gpt-oss-20b` model through Groq. The instructions tell the model to use only the retrieved context and to clearly say when the guide does not contain enough information.

### 8. Asked questions in two ways

The completed chain is used for:

- A single example question about international roaming.
- An interactive question loop where a person can keep asking questions until they enter `quit`, `exit`, or `q`.

The interactive version streams the answer, so text appears gradually instead of waiting for the whole response to finish.

### 9. Inspected the retrieved evidence

The final section asks about SIM swap fraud and prints the exact chunks found by the search, including their page numbers, before generating the answer.

This is a useful debugging step because it shows whether a poor answer was caused by the search finding the wrong text or by the AI misunderstanding useful text.

## How Information Flows

```text
Telecom PDF
    -> extracted text
    -> small overlapping chunks
    -> embeddings (numerical meaning)
    -> ChromaDB

User question
    -> find the three closest chunks
    -> give chunks and question to the AI model
    -> return a grounded answer
```

## Why RAG Is Useful

- It lets an AI assistant answer from a specific document.
- It reduces the chance of the model inventing unsupported information.
- It can find related information even when the question uses different wording.
- It allows the retrieved source text to be inspected when an answer looks incorrect.
- The source document can be changed without retraining the AI model.

## Important Limitations

- RAG improves reliability but does not guarantee that every answer is correct.
- The search always returns the nearest available chunks, even when none is a strong match.
- An answer can be incomplete if the needed information is spread across more than three chunks.
- PDF extraction may be inaccurate for scanned pages, tables, or complex layouts.
- The quality of the final answer depends on both the retrieved text and the AI model.
- This demo does not display formal source citations in the final answer, although page details are available in the retrieved metadata.

For important decisions, the answer should still be checked against the original telecom guide.

## Running the Notebook

1. Place `telecom_guide.pdf` in the same folder as the notebook.
2. Add `GROQ_API_KEY` to the `.env` file in the project root.
3. Select the project's `.venv` Python kernel in VS Code.
4. Run the notebook cells from top to bottom.

The order matters because later cells use objects created by earlier cells. After restarting the kernel, run all cells again before asking a question. Otherwise, Python may report that an object such as `chain`, `retriever`, or `vector_db` is not defined.

## Simple Glossary

- **AI model / LLM**: A system that reads and generates human-like text.
- **RAG**: A method that finds relevant source material before asking an AI model to answer.
- **Chunk**: A small section of a larger document.
- **Embedding**: A numerical representation of the meaning of text.
- **Vector database**: A database designed to find items with similar meanings.
- **Retriever**: The part that searches for the most relevant chunks.
- **Prompt**: The instructions and information sent to the AI model.
- **Context**: The retrieved source text given to the model for answering a question.
